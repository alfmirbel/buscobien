## Notas

- **Patrón idéntico 7x**: Los 7 providers (`provider_menu_*.dart`) siguen **exactamente el mismo patrón**: clase `ElementosDelMenuX` (state con `index`, `etiqueta`, `icono`, `List<bool> buttonSelectOpcion`, `List<ElementosMenus> elementosMenuX`, `TabController`, `int seleccionMenuX`) + clase `ClaseMenuX extends StateNotifier<ElementosDelMenuX>` con los mismos métodos (`inicializaController`, `disposeController`, `asignaNuevaOpcionSeleccionada`, `restableceOpcionActualSeleccionada`, `asignaNuevoIconoEtiqueta`, `getTamanioListaElementos`). Variaciones: número de items (3, 4 ó 5) y los iconos/etiquetas específicos de cada uno.
- **StateNotifier vs Riverpod Generator**: este subdirectorio **no usa** `@riverpod` codegen; todos son `StateNotifierProvider` clásico de `flutter_riverpod/legacy.dart`. No requiere `.g.dart`.
- **Items detallados**: ver `02_Epics_EARS/05_provider_menus.md` (tabla de trazabilidad) para lista exacta de etiquetas de cada menú.
- **Nibdb binding bidireccional**: `asignaNuevaOpcionSeleccionada(ref, index)` actualiza state; `restableceOpcionActualSeleccionada(ref)` sincroniza el `TabController.index` desde el `seleccionMenuX` (vuelve atrás cuando proviene de cambio externo). El widget `ButtonsTabBar.onTap` invoca `asignaNuevaOpcionSeleccionada` + `actualizarX` en `homeNavigationProvider` → propagate abajo. Escucha desde `homeNavigationProvider.indiceX` ejecuta `asignaNuevaOpcionSeleccionada` → propagate arriba.
- **`ValueKey` dinámicos**: presentes en 5/5 SliverAppBars para evitar el error `Multiple elements with same key` al reconstruir tabs. Patrón: `ValueKey('menuX-${tabController.index}')`.
- **`MenuSuperiorPaginaTucuenta` / `...Usuario`**: `toolbarHeight: 0` (sin título arriba del tabbar); `pinned: true`. onTap invoca `actualizarMiCuenta(index)` / `actualizarMiCuentaUsuario(index)` para sincronizar con `homeNavigationProvider` (binding al shell principal).
- **`MenuInferiorTipoDeTransaccion`**: a diferencia de los demás SliverAppBars, es widget standalone que se renderiza en el cuerpo (no como `sliver`). No lleva `SliverAppBar`; usa `Container + ButtonsTabBar` en bottom del cuerpo.
- **`dropdown_menu_principal_propiedades.dart`**: usa variable **global mutable** `selectedDropDownMenuPrincipalValue` (declarada en `lib/02_principal_screen/principal_sliver_screen_menus_inicio.dart`). Callback `onChangedCallback` notifica cambios a listeners. Lista de tipos viene de `otrosTiposDeInmueble` (constante en `lib/08_pantallas/tu_cuenta/tus_espacios/tabla_tipopropiedad_vs_campos.dart`).
- **`appbar_sliver_menu_inicial` y `appbar_sliver_menu_principal`**: declaran alias `manuPrincipal` (sic, typo) — **deuda técnica menor de naming**.

## Deuda técnica detectada

1. **7x copy-paste** del patrón StateNotifier — candidato a `MenuProviderBase<T>` genérico.
2. **Variable global mutable** `selectedDropDownMenuPrincipalValue` compartida entre `02_principal_screen` y `05_provider_menus` — acoplamiento oculto.
3. **`MenuSuperiorPaginaInicioNivelGobierno`**: longitud de tabs calculada en UI (no en provider) → mezcla lógica de presentación y datos.
4. **`TabController` lifecycle**: depende de `disposeController()` se llame al desmontar el shell — riesgo si no se invoca en todos los caminos de dipose.
5. **Sin tests** de sincronización `TabController ↔ Notifier`.
