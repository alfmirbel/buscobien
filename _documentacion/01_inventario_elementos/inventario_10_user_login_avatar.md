# Inventario de Componentes - `lib/10_user_login/avatar`

Este documento contiene un inventario técnico exhaustivo y estructurado de los archivos en el subdirectorio de gestión de avatares de perfil de usuario **`D:\buscobien\lib\10_user_login\avatar`**.

El motor de avatar permite la captura mediante selector de archivos en el dispositivo, la serialización/deserialización de metadatos e imágenes codificadas en Base64, y la sincronización síncrona/asíncrona mediante providers de Riverpod para interactuar de manera directa con CouchDB.

## Análisis Técnico y Observaciones sobre el Motor de Avatar

1. **Gestión Binaria de Imágenes en CouchDB:**
   * El notifier `ClassUserAvatarNotifier` implementa dos variantes de almacenamiento en base de datos. Para registrar un avatar nuevo, codifica las credenciales mediante cifrado base64 básico y realiza una carga `PUT` binaria directa a la base de datos de CouchDB (`buscobien_avatares`). Al actualizar un avatar existente, pasa el parámetro de revisión (`?rev=`) en la URL HTTP para que CouchDB realice el reemplazo seguro del adjunto anterior sin duplicar metadatos obsoletos.

2. **Decodificación Reactiva Segura para Previsualización:**
   * La interfaz de `GestionAvataresState` combina un buffer dinámico local `filesGet` (de tipo `Uint8List`) con el escuchador `ref.watch(classUserAvatarProvider)`. Al invocar al selector nativo `FilePicker`, se lee asíncronamente el archivo de forma local en bytes (`readAsBytes`), se convierte a base64, y se refresca visualmente mediante `convierteData2Imagen()` antes de comprometer la transacción final a CouchDB. Esto permite previsualizaciones sin retraso en la pantalla del dispositivo.

3. **Estructura Histórica de Referencia (Código Comentado):**
   * El archivo `manejo_imagenes_avatar.dart` cuenta con una gran sección de código histórico comentado (desde la línea 341 hasta la 1151) que documenta las fases previas de integración con Riverpod, sirviendo como guía de referencia evolutiva del backend en la aplicación.
