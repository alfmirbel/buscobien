# Inventario de Componentes - `lib/10_user_login/usuario_login`

Este documento detalla el inventario de componentes técnicos definidos en cada archivo `.dart` dentro de la sección **`D:\buscobien\lib\10_user_login\usuario_login`**.

Esta sección es el núcleo operativo de la autenticación de Buscobien. Provee pantallas interactivas para login y registro, administra la persistencia de datos local segura mediante `FlutterSecureStorage`, y encapsula el repositorio HTTP y los providers de Riverpod que regulan la sesión activa en tiempo real contra CouchDB.

## Análisis y Conclusiones del Módulo de Autenticación

1. **Robustez Multiusuario y Cambio Dinámico de Roles:**
   * La clase `SessionNotifier` implementa una arquitectura muy robusta con `setPerfilUsuarioByNombrePerfil`. Al seleccionar un perfil (por ejemplo: `Promotor`), el sistema de forma mutuamente excluyente habilita los privilegios del rol y reconstruye de manera atómica el estado `AuthState`. Esto asegura que el ruteo y visualización de secciones protegidas (como "Tus Espacios") respondan sin demoras.

2. **Seguridad y Criptografía Irreversible de Contraseñas:**
   * En `session_repository.dart`, el método `writeUserToCouchDB` combina el nombre de usuario, la contraseña del input y un `DateTime.now().toString()` (utilizado como sal criptográfica) mediante la función `generateSHA256Hash()` para generar un ID único irreversible de usuario. Adicionalmente, cifra con SHA-256 la clave de acceso antes de comprometer el documento en CouchDB. Esto previene de raíz que claves en texto plano residan en base de datos.

3. **Estrategia Adaptativa para Documentación Legal (Móvil vs Web):**
   * El registro de usuarios en `login_03_form_register_user.dart` incorpora un mecanismo adaptativo muy avanzado. Si el usuario desea descargar los Términos y Condiciones en Web (`kIsWeb`), abre y visualiza el PDF directamente en una nueva pestaña del navegador utilizando `launchUrl()`. Si se encuentra en un dispositivo móvil (Android/iOS), el sistema extrae los bytes del asset local, escribe un archivo temporal en disco con `path_provider`, y lo despliega mediante el visor nativo integrado de `OpenFilex`.
