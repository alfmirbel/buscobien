# Inventario de Componentes - `lib/12_localidades_user`

Este documento contiene el inventario técnico de los componentes definidos en cada archivo `.dart` en el directorio **`D:\buscobien\lib\12_localidades_user`**.

Este módulo es responsable de gestionar la geolocalización de los usuarios de Buscobien mediante la vinculación de cuentas de usuario con asentamientos específicos, códigos postales y coordenadas geográficas. Interactúa estrechamente con el catálogo SEPOMEX de códigos postales y sincroniza de forma fluida la ubicación activa del usuario con las variables de sesión reactivas controladas mediante Riverpod.

## Análisis Técnico y Arquitectura de las Localidades de Usuario

1. **Gestión Inmutable y Deserialización Rígida con Freezed:**
   * La estructura de datos de localidades de usuario utiliza anotaciones de `Freezed` para lograr una representación 100% inmutable. Esto es crucial cuando se manejan estados interactivos compartidos, ya que garantiza que ninguna modificación lateral de un widget altere los datos en memoria sin pasar explícitamente por un método `copyWith()` que transicione el estado en Riverpod.

2. **Evitación de Colisiones y Validación de Duplicados (CouchDB):**
   * En [localidades_repository.dart](file:///D:/buscobien/lib/12_localidades_user/localidades_repository.dart), el método `saveUserLocalidad()` realiza un paso defensivo brillante antes de persistir una nueva localidad. Consulta la vista de CouchDB `vistaUserAsentamiento` para el par de claves `[idUsuario, asentamiento]`. Si recibe una coincidencia (indicando que el usuario ya tiene vinculada esa localidad), retorna un código de estado intermedio `409` (Conflict), evitando de manera proactiva la duplicación de datos en base de datos sin incurrir en transacciones costosas.

3. **Sincronización Bidireccional de Ubicaciones Activas:**
   * En [provider_get_localidades_usuario.dart](file:///D:/buscobien/lib/12_localidades_user/provider_get_localidades_usuario.dart), cuando un usuario selecciona una localidad ya sea a través de `setUserLocalSelectedFromLocalidades()` o mediante `setUserLocalFromUserLocalGet()`, el Notifier no solo muta su propio estado `UsuarioLocalidadesGet`, sino que de manera paralela invoca a `ref.read(sessionProvider.notifier).updateLocalidadEnSesion(locData.localidadCp)`. Esto propaga instantáneamente el cambio a todos los componentes que dependen de la sesión del usuario (por ejemplo, filtros de búsqueda de inmuebles contextualizados por la ubicación actual).
